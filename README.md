# PerekupBot MVP

Бот отслеживает новые объявления о продаже автомобилей в Татарстане, Чувашии и Марий Эл. Для доступных аккаунту Telegram-каналов сообщения приходят через официальный Telegram API и дополнительно сверяются по расписанию. Объявление сохраняется в PostgreSQL, проверяется на дубли, сопоставляется с настройками пользователя и отправляется в Telegram. Повторное объявление не отправляется; снижение цены создает отдельное уведомление.

## Быстрый запуск

1. Скопируйте `.env.example` в `.env` и задайте `TELEGRAM_BOT_TOKEN` от BotFather. Секреты не добавляйте в Git.
2. Для перечисленных публичных каналов получите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` для своего Telegram-аккаунта на [my.telegram.org](https://my.telegram.org). Аккаунт должен иметь доступ к каналам и чатам, которые вы хотите читать. При необходимости вступите в них обычным способом. Сервис не вступает в чаты автоматически. Если бот добавлен в собственный канал, сообщения этого канала также принимаются напрямую через Bot API без пользовательской сессии.
3. Выполните `docker compose build`, затем `docker compose up -d db redis`.
4. Авторизуйте аккаунт: `docker compose run --rm -it worker python -m app.tools.telegram_login`. Введите номер, код и облачный пароль, если Telegram запросит. Файл сессии сохранится в `./data/telegram.session` и останется локально.
5. Запустите приложение: `docker compose up -d`. Проверка API: `curl http://127.0.0.1:8000/health`. Если порт занят, задайте другой `API_PORT` в `.env` и используйте его в URL. Логи: `docker compose logs -f worker`.
6. Напишите боту `/start`, откройте `/settings` и выберите бюджет, регионы, города и источники. В меню есть инструкция `/help`, управление фильтрами и кнопка остановки поиска.

При первом подключении пользовательского Telegram-источника текущие старые посты пропускаются. Новые посты и редактирование цены отслеживаются далее. Если аккаунт не авторизован, бот работает; для каналов, где он участник, Bot API продолжает принимать новые посты. `TELEGRAM_ADMIN_ID` задаёт владельца: только он открывает `/admin` и назначает/отзывает пользовательский доступ. `TELEGRAM_ADMIN_IDS` задаёт дополнительных администраторов, которые сохраняют доступ к боту, но не могут управлять тарифами. В админ-панели можно заранее выдать тариф по `@username` или числовому Telegram ID. Ожидающий доступ действует 30 дней; после первого `/start` выбранный тариф включается на установленный для него срок, а «Команда» — бессрочно. Сам `/start` без назначенного тарифа доступ не открывает. По истечении срока пользователь перестаёт получать объявления.

## Тарифы — коммерческое предложение

Владельцу доступны пять тарифных меток в `/admin`. Четыре тарифа открывают базовый доступ на 30 дней, а «Команда» за 14 990 ₽ действует бессрочно. \* Предлагаемые пакеты; эти квоты, места и SLA пока не применяются ботом. Сейчас сообщения из Telegram-каналов могут обрабатываться сразу, а Apify-источники Auto.ru, Drom и Avito проверяются примерно раз в час. Снижение интервала увеличивает расходы на Actors, поэтому ускоренные уровни нужно включить после замены/оптимизации парсеров и замера фактической стоимости. Дополнительный отчёт можно планировать по 150 ₽: при заданной себестоимости 90 ₽ остаётся 60 ₽ до расходов на интеграцию, налоги и поддержку. Перед продажей отчётов необходимо подтвердить доступ к официальному API/оптовому пакету и условия перепродажи; указанная себестоимость не подтверждает право перепродажи.

## Настройки поиска в боте

В `/settings` пользователь может выбрать бюджет (готовые суммы или число только из цифр), географию (89 регионов из справочника, все города региона или ручной выбор), источники и автомобиль. Марки и модели выбираются в отдельном кнопочном каталоге в главном меню, поэтому пользователь не вводит их вручную с возможными опечатками. Раздел «Тариф и поддержка» показывает текущий план, позволяет отправить запрос на смену тарифа и передать сообщение владельцу бота; владелец отвечает прямо на пересланное обращение. Поиск можно остановить и возобновить; остановленный пользователь перестаёт получать уведомления и не учитывается при решении, нужен ли общий опрос соответствующего источника. Источники общие: если их оставил хотя бы один пользователь с доступом, источник продолжит опрашиваться.

Географический справочник городов создан на основе [pensnarik/russian-cities](https://github.com/pensnarik/russian-cities) (авторы указывают Википедию как исходный источник); четыре дополнительные региональные записи добавлены вручную. Выбранная география фильтрует результаты и не расширяет покрытие сборщиков сама по себе: сейчас Telegram-каналы подключены только для Татарстана, Чувашии и Марий Эл, а внешние Actors Авито, Auto.ru и Дром настроены на Казань. Для сбора из других регионов потребуется добавить соответствующие источники/поисковые URL и учесть лимит Apify.

В следующей итерации к пакетам логично добавить общий поиск по площадкам и Telegram, расширенные фильтры по региону/городу/бюджету, историю цены и быстрый контакт с поддержкой. Сначала следует замерять их себестоимость и включать только те функции, которые сервис может стабильно выполнить.

## Источники

Список хранится в [app/config/sources.json](app/config/sources.json). Измените файл и перезапустите worker: источники синхронизируются с таблицей `sources`, а курсоры сообщений сохраняются. Для Telegram задайте `kind: telegram`, `identifier` как публичный username канала и регион. Частота каждого collector задается через `interval_seconds`, минимум 15 секунд; значение по умолчанию в конфигурации 30 секунд. События каналов, где аккаунт состоит участником, обрабатываются сразу. Сверка последних сообщений покрывает пропущенные события и редактирования. Соблюдайте лимиты Telegram и увеличивайте интервалы при `FloodWait`.

Avito, Auto.ru и Drom реализованы как независимые адаптеры к Apify. `APIFY_TOKEN` хранится только в локальном `.env`. Все три источника включены для Казани с интервалом 3600 секунд и ограничением до 20 результатов за запуск. Клиент Apify передает это ограничение как `max_items`; для Avito также задан предел оплаты $0.10 на запуск, а Actor использует инкрементальный режим. Для других городов измените `identifier` как Actor ID и `config.input`. Примерные Actors:

- [Avito Listings](https://apify.com/zen-studio/avito-listings-scraper): `zen-studio/avito-listings-scraper`; принимает `searchUrl`, выдает `id`, `title`, `price`, `images`.
- [Auto.ru](https://apify.com/getascraper/autoru-scraper): `getascraper/autoru-scraper`; принимает `citySlug`, выдает `listingId`, `price`, `mileageKm`, `sellerType`. Режим Actor `onlyChangedListings` возвращает неполные события, поэтому для основного поиска оставьте его выключенным.
- [Drom](https://apify.com/getascraper/drom-ru-cars-scraper): `getascraper/drom-ru-cars-scraper`; принимает `citySlug`, выдает `bullId`, `price`, `mileageKm`, `photos`.

Эти Actors поддерживаются сторонними авторами; их полнота, скорость и стоимость могут меняться. Пробные запуски Avito, Auto.ru и Drom вернули объявления для Казани. `VKCollector` оставлен явной точкой расширения и выключен: для него нужен выбранный метод доступа VK API, токен и список групп. Он не возвращает фиктивные данные. `MockCollector` использует `config.items` и подходит для локальной проверки pipeline без внешнего источника.

## Архитектура

`BaseCollector` → `ListingInput` → нормализация → поиск дублей → `listings` и `price_history` → фильтры → оценка → `notifications` → Telegram. Схема БД создается миграцией Alembic. Таблицы: `users`, `user_filters`, `sources`, `listings`, `listing_aliases`, `listing_photos`, `price_history`, `notifications`, `collector_runs`. Redis удерживает lock на время запуска каждого collector; worker выполняет фоновые циклы и обработку событий. Уведомления со статусом `pending` или `failed` проверяются раз в минуту; после ошибки отправки пауза постепенно растет до одного часа. Атомарное резервирование уведомления предотвращает одновременную отправку из двух обработчиков; после аварии резерв снимается через 10 минут. Поля `published_at`, `first_seen_at`, `notification_sent_at` сохраняются; задержки обнаружения и отправки выводятся в логи, если источник дает время публикации.

Дедупликация использует ID в рамках источника, URL, телефон вместе с признаками автомобиля, затем марку/модель/год/цену/город и сходство текста. Для текстов Telegram правила извлекают марку, модель, цену, год, пробег и город; интерфейс `ListingExtractor` позволяет заменить их другим обработчиком. Оценка 0–100 основана на простых признаках и не содержит предположений о рыночной цене или марже.

## Проверка

Тесты правил и сохранения событий: `docker compose run --rm api python -m unittest discover -s tests -v`. При наличии локального Python 3.11+ и зависимостей можно выполнить ту же команду напрямую. Для ручной проверки доставки добавьте в `sources.json` временный источник `mock` с `config.items`, включите его, перезапустите worker и проверьте сообщение в боте. Меняя цену того же `external_id`, можно проверить уведомление о снижении.

## Ограничения MVP

Без действующих Telegram credentials приложение не может получать Telegram-объявления или отправлять сообщения; Apify требует отдельный ключ. Доступ к Telegram-сообщениям определяется правами авторизованного аккаунта. Сверка Telegram проверяет последние 25 сообщений, поэтому редактирование более старого поста обнаруживается только через событие канала, которое приходит участнику. Для внешних Actors время публикации иногда отсутствует в выдаче, поэтому `detection_delay` тогда не вычисляется. Telegram Bot API не поддерживает ключ идемпотентности для отправки: при аварийном завершении процесса между успешной отправкой и записью `sent` возможен повтор. В штатном цикле уникальный ключ уведомления исключает повторную отправку.
